# UNITAS 技术笔记

UNITAS 用**轨迹 tokenizer**把每个 3D 点的整段运动编码为一个 token，用 **Rectified Flow** 生成未来轨迹和机器人控制指令，并用**数据对齐**把视觉观测、动作和场景变化放进同一个米制 3D 参考系。

排版沿用手写笔记的层次。黑笔为正文，*蓝笔为斜体小标题与引用块中的推导*，**绿笔为粗体补充**。

## 论文概览

**UNITAS: A 3D-NATIVE WORLD ACTION MODEL FOR EMBODIED MANIPULATION**

现有多数世界动作模型（World Action Models，WAM）以预训练的视频生成模型为基础，用图像或视觉 latent 表示环境的变化。机器人交互则发生在有物理尺度的三维空间中。图片里的像素距离会随视角和深度变化，无法直接表征夹爪与物体之间的实际距离。

**UNITAS 的核心贡献是在每个交互窗口内，将视觉观测、动作流和场景流统一到同一个米制 3D 参考系。** 机器人夹爪和人手采用共同的点轨迹表示。基于物理时间的轨迹 tokenizer 把每个点的整段运动编码成一个 token，并用该点当前的 3D 位置为 token 提供空间锚点。

| 表示 | 含义 | 以插花为例 |
| --- | --- | --- |
| **动作流（action flow）** | 人手或机器人夹爪上的点随时间移动的 3D 轨迹。 | 夹爪指尖沿什么路径移动。 |
| **场景流（scene flow）** | 给定动作流后，场景查询点随时间变化的 3D 位移。 | 沿这条夹爪轨迹运动时，花上的点预计怎样移动。 |
| **机器人控制指令（action chunk）** | 可执行的末端相对平移、旋转和夹爪开度序列。 | 末端怎样平移和旋转，夹爪每一步张开多少。 |

论文和项目资料。[UNITAS 论文](https://arxiv.org/abs/2610.12099) · [项目主页](https://unitas-wam.github.io/)

## 模型结构与图 2

UNITAS 共有约 **17 亿参数**。Florence-2-large 编码视觉和任务指令。两个逐层耦合的 Diffusion Transformer（DiT）分别负责 3D 点轨迹和机器人控制指令。

| 模块 | 规模 | 作用 |
| --- | --- | --- |
| **视觉语言骨干** | Florence-2-large，570.7M | 编码主视角 RGB 和语言指令。辅助视角复用视觉编码器，视觉 token 加入世界坐标系下的 3D 位置编码。 |
| **点动力学专家（Point Dynamics DiT）** | 28 层，宽度 1280，20 个注意力头，826.3M | 预测人手或夹爪点的动作流，并以动作流为条件预测场景流。 |

| **轨迹 tokenizer** | 256 维 latent，1.9M | 每条点轨迹对应一个 token，并可按物理时间解码。单独训练后冻结。 |
| **嵌入与投影层** | 39.7M | 对齐不同模态的特征维度并加入空间信息。 |

## 训练流程概览

1. **先训练轨迹 tokenizer。** 对每个夹爪点、人手关键点或场景点，把整段相对 3D 位移轨迹编码为 256 维 latent。解码器根据查询时间恢复位移，编码器和解码器共同最小化重建误差。详见「轨迹 Tokenizer」。
2. **冻结 tokenizer，再用 Rectified Flow 联合训练主模型。** 三个预测目标分别是未来动作流 latent、场景流 latent 和机器人控制指令。示范动作流一方面加噪作为动作流分支的输入，另一方面以干净版本为场景流分支提供条件。详见「Rectified Flow」。

**几何对齐在构建训练数据时建立，动作与后果的关系由模型从训练样本中学习。**

- **对齐观测与轨迹。** 作者用相机标定和可用深度把视觉观测中的位置映射到共享坐标系，再用同一参考系表示夹爪点和场景点的轨迹。一个机器人训练窗口把视觉观测、语言指令、末端状态和已有的运动与控制标签配对。这里的世界坐标系是窗口内固定的米制参考系，例如机器人基座坐标系。
- **配对动作与后果。** 场景流分支读取示范中的未来夹爪轨迹，以同一窗口内场景点的后续位移作监督。论文的场景流监督来自仿真。各数据源根据已有标注参与相应的损失计算。详见「训练数据对齐」。

## 1. 轨迹 Tokenizer

### 输入与输出

Tokenizer 是一个**按物理时间条件化的自编码器**。对第 $`n`$ 个点，设 $`t`$ 为当前时刻，$`f`$ 为有效采样率，$`H`$ 为未来采样步数。编码器读取未来各时刻的 3D 位移与时间偏移，输出一个 256 维向量 $`z_n`$。解码器给定 $`z_n`$ 和查询时间，恢复该时刻的 3D 位移。

```math
\tau_k=\frac{k}{f},\qquad
\Delta \mathbf{x}_{n,k}
=\mathbf{x}_{t+\tau_k,n}-\mathbf{x}_{t,n},
\qquad k=1,\ldots,H.
```

> *符号与例子*  
> $`k`$ 是采样步，$`n`$ 是点的索引，$`\mathbf{x}_{t,n}`$ 是该点当前的 3D 位置。以 10 Hz 采样时，$`k=2`$ 对应 0.2 秒，该时刻的位移相对于预测起点计算。$`H`$ 个未来位移与起始位置一起，能表示 $`H+1`$ 个位置。

### 编码、解码与训练

**编码器**先把每个时刻的位移映射到特征空间，再按该时刻的时间编码做 FiLM 调制，最后沿时间维度汇聚。Padding 项从求和中排除。

```math
\begin{aligned}
h_{n,k} &= \mathrm{MLP}_{\mathrm{in}}(\Delta \mathbf{x}_{n,k}),\\
z_n &= \frac{1}{\sqrt H}\sum_{k=1}^{H}
\left[(1+a_k^{\mathrm{enc}})\odot h_{n,k}+b_k^{\mathrm{enc}}\right].
\end{aligned}
```

#### *时间戳怎样变成 FiLM 参数*

先用固定公式把标量时间偏移 $`\tau_k`$ 编码为向量 $`e_k`$，再用可训练的时间 MLP 输出逐通道缩放和偏移。UNITAS 在各数据源上共用 $`T_{\max}=3\,\mathrm{s}`$，时间编码维度为 $`d_z=256`$。未来和历史分别使用正、负时间偏移。

```math
[e_k]_j
=
\operatorname{sgn}(\tau_k)
\sin\!\left[
\frac{\pi}{2}
\left|\frac{\tau_k}{T_{\max}}\right|^{j/d_z}
\right],
\qquad j=0,\ldots,d_z-1.
```

```math
\begin{bmatrix}
a_k^{\mathrm{enc}}\\
b_k^{\mathrm{enc}}
\end{bmatrix}
=
\mathrm{MLP}^{\mathrm{enc}}_{\mathrm{time}}(e_k),
\qquad
a_k^{\mathrm{enc}},b_k^{\mathrm{enc}}\in\mathbb{R}^{256}.
```

> *先调制，再求和*  
> 同一时刻的各个点共享 FiLM 参数，各点保留自己的位移特征。即使两个时刻都对应向上 5 cm，时间条件也会改变这两个位移特征对 $`z_n`$ 的贡献。

**解码器**用自己的时间 MLP 从 $`e_k`$ 得到 $`a_k^{\mathrm{dec}},b_k^{\mathrm{dec}}`$，用它们调制同一个 $`z_n`$，再输出所查询时刻的位移。把预测位移加回起始 3D 坐标，即可恢复未来点的位置。

```math
\widehat{\Delta \mathbf{x}}_{n,k}
=
\mathrm{MLP}_{\mathrm{out}}
\left[(1+a_k^{\mathrm{dec}})\odot z_n+b_k^{\mathrm{dec}}\right],
\qquad
\widehat{\mathbf{x}}_{t+\tau_k,n}
=
\mathbf{x}_{t,n}+\widehat{\Delta \mathbf{x}}_{n,k}.
```

**训练**在有效的点和时刻上最小化平方欧氏重建误差。历史和未来动作流的重建损失取平均，再加上可用的场景流重建损失。训练结束后冻结 tokenizer，用训练集统计量逐通道标准化 latent，再交给主模型训练。

```math
\mathcal{L}_{\mathrm{rec}}
=
\frac{1}{|\mathcal V|}
\sum_{(n,k)\in\mathcal V}
\left\|\widehat{\Delta \mathbf{x}}_{n,k}
-\Delta \mathbf{x}_{n,k}\right\|_2^2.
```

这里 $`\mathcal V`$ 是某一类轨迹中有效的点与时刻对。

**夹爪点、人手关键点和场景点共用这一套 tokenizer。主模型每个点只处理一个轨迹 token，并额外用该点的初始 3D 位置作为空间锚点。**

## 2. Rectified Flow

### 输入与输出

设 $`y`$ 为干净目标，$`\epsilon\sim\mathcal N(0,I)`$ 为同形状的高斯噪声，$`\gamma\in[0,1]`$ 为生成进度，$`c`$ 为该分支的条件。DiT 根据当前带噪状态 $`y_\gamma`$、$`\gamma`$ 和 $`c`$ 预测速度向量 $`v_\theta`$，其中 $`\theta`$ 是模型的可训练参数。

```math
y_\gamma=(1-\gamma)\epsilon+\gamma y,\qquad
\mathcal L_{\mathrm{flow}}
=
\left\|v_\theta(y_\gamma,\gamma,c)-(y-\epsilon)\right\|_2^2.
```

#### *为什么训练目标是 数据与噪声之差*

对一对固定的噪声与干净目标，沿两者之间的直线路径对 $`\gamma`$ 求导，得到该训练样本的监督速度。

```math
\frac{d y_\gamma}{d\gamma}
=
\frac{d}{d\gamma}\big[(1-\gamma)\epsilon+\gamma y\big]
=
y-\epsilon.
```

> *两个时间变量*  
> $`\gamma`$ 表示生成进行到哪一步，$`v_\theta`$ 是目标表示随 $`\gamma`$ 的变化率。$`\tau_k`$ 表示距当前观测时刻的物理时间偏移。

### 与 Flow Matching 的关系

就训练目标而言，**Rectified Flow 是 Flow Matching 采用线性插值时的一个特例**。Flow Matching 可以使用不同的条件概率路径，包括扩散型路径。在常见的高斯条件路径下，可以用 $`\alpha(\gamma)`$ 和 $`\sigma(\gamma)`$ 决定干净样本和噪声在各时刻的权重。

| 方法 | 训练路径 $`y_\gamma`$ | 速度监督 $`dy_\gamma/d\gamma`$ |
| --- | --- | --- |
| **Flow Matching 的一种常见形式** | $`\alpha(\gamma)y+\sigma(\gamma)\epsilon`$ | $`\alpha'(\gamma)y+\sigma'(\gamma)\epsilon`$ |
| **UNITAS 使用的 Rectified Flow** | $`\gamma y+(1-\gamma)\epsilon`$ | $`y-\epsilon`$ |

取 $`\alpha(\gamma)=\gamma`$、$`\sigma(\gamma)=1-\gamma`$，就得到 UNITAS 的公式。在标准高斯噪声与数据样本独立配对、终点残余噪声 $`\sigma_{\min}=0`$ 的设定下，这也对应 Lipman 等人论文中线性条件路径的训练目标。

> *训练路径是直线，推理轨迹为什么还能弯曲？*  
> 对同一对 $`(\epsilon,y)`$，监督速度 $`y-\epsilon`$ 沿线恒定。不同训练配对却可能在同一生成时刻经过同一位置，提供不同的速度目标。模型只能在该位置给出一个速度，因此在均方误差下学习的是给定当前位置、生成进度和条件后的平均速度。对这个共享速度场做积分，得到的推理轨迹仍可能弯曲。

#### *Reflow 如何让推理轨迹更直*

先用已训练的模型从噪声 $`\epsilon`$ 积分到生成结果 $`\hat y`$，再用模型产生的新配对 $`(\epsilon,\hat y)`$ 做一轮线性插值和速度回归。每轮使用同样的速度回归形式，改变的是噪声与端点的配对。这样可以使推理轨迹更直，便于用更少的积分步数采样。

**UNITAS 论文描述了线性插值和速度回归，未报告额外的 reflow 阶段。**

原始论文：[Flow Matching for Generative Modeling](https://arxiv.org/abs/2210.02747) · [Flow Straight and Fast](https://arxiv.org/abs/2209.03003)

### 三个训练目标与推理

UNITAS 用两个逐层耦合的 DiT。Point Dynamics DiT 负责动作流和场景流，Action DiT 通过共享的观测与语言 K/V 生成机器人控制指令。

| 分支 | 干净目标 $`y`$ | 预测条件 $`c`$ |
| --- | --- | --- |
| **Action flow** | 夹爪或人手关键点的未来轨迹 latent | 当前观测、语言指令、历史动作流及动作点的当前 3D 位置 |
| **Scene flow** | 场景点的未来轨迹 latent | 同一交互的观测、语言和历史，另加场景查询点的初始 3D 位置和示范中的干净未来动作流 |
| **Robot commands** | 未来各步的末端相对平移、旋转和夹爪开度 | 共享观测与语言特征、当前末端状态 |

训练时，同一段示范动作轨迹编码得到 $`A_{\mathrm{clean}}`$。它直接为场景流提供条件，也经加噪得到 $`A_\gamma`$，供动作流分支学习生成轨迹。三项损失的权重各为 1，另加权重为 0.1 的 3D 位置编码损失。

推理时，从高斯噪声出发，用 DiT 预测速度并做 Euler 更新，得到轨迹 latent 或控制指令。生成或外部给定的动作流可以继续用于场景预测。只执行机器人控制时，可以直接生成控制指令。

**Rectified Flow 定义训练目标与采样方法，DiT 实现速度场 $`v_\theta`$。一般也可以用 U-Net 或 MLP 实现速度场。UNITAS 用 Transformer 在观测、语言和轨迹 token 之间做注意力交互。**

## 3. 训练数据对齐

### 样本如何组织

UNITAS 按**同一条示范中的当前时刻 $`t`$**切出训练窗口。该窗口包含当前观测、任务指令、历史动作流，以及已有的未来动作流、场景流和控制标签。观测和点轨迹共享窗口内固定的米制 3D 坐标系。机器人数据通常用机器人基座或本体共享坐标系，第一人称人手数据用窗口锚点的相机坐标系。

### 空间对齐

| 数据 | 怎样映射到训练窗口 |
| --- | --- |
| **视觉观测** | 对有深度的像素，用相机内参和深度反投影，再用外参变换到共享坐标系。把对应的 3D 位置编码加到视觉 token 上。 |
| **动作流** | 对每条机械臂，在夹爪的 URDF 几何上选 20 个固定点，保存它们的连杆局部坐标。用每帧的关节状态做正向运动学，把同一批点转到共享坐标系。人手数据用每只可见手的 21 个 MANO 关键点，并用相机位姿把轨迹转到窗口锚点坐标系。 |
| **场景流** | 用 URDF 和当前关节状态遮去机器人像素，再从剩余 RGB-D 像素反投影并采样场景查询点。仿真状态提供同一批场景点在未来时刻的对应位置。 |
| **控制标签** | 把同一窗口内的末端相对平移、旋转和夹爪开度作为控制分支的标签，与同段示范的夹爪点轨迹配对。 |

#### *像素怎样进入共享坐标系*

设 $`d`$ 是像素 $`(u,v)`$ 的深度，$`K`$ 为相机内参，$`R,\mathbf t`$ 为相机到共享坐标系的刚体变换。

```math
\mathbf p_{\mathrm{cam}}=dK^{-1}[u,v,1]^\top,\qquad
\mathbf p_{\mathrm{world}}=R\mathbf p_{\mathrm{cam}}+\mathbf t.
```

> *纯 RGB 的处理*  
> 模型在已标定的相机射线上，从 0.1 到 2.0 米采样 64 个候选深度，用 patch 视觉特征给候选点的位置编码加权。有深度时，真实深度派生的 Fourier 位置特征提供监督。具体的场景流查询点由深度或已有几何给出初始 3D 坐标。

### 时间对齐与监督

动作流和场景流共用当前时刻 $`t`$，各步都用物理时间偏移 $`\tau_k=k/f`$ 表示。RoboTwin 的 **15 Hz、20 步**覆盖约 **1.33 秒**，LIBERO 的 **20 Hz、20 步**覆盖 **1 秒**。Tokenizer 用以秒为单位的时间条件处理两种轨迹。

例如，在一段插花示范中，场景分支读取接下来这段时间的**夹爪 3D 轨迹**，用同一段时间里**花上的点实际怎样移动**作为监督。点的初始位置、未来位置和夹爪轨迹都在同一坐标系中。

**场景流监督来自仿真。不同来源可以提供不同的标注，缺失的监督项会被掩码跳过。这样，混合训练可以同时利用仿真、真机和人手示范。**
